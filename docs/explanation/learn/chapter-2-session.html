Chương 2 · Session

Mỗi lần chạy phải có bộ nhớ riêng

Nhu cầu: kernel dùng chung cho mọi run. Nhưng mỗi task đang chạy cần sổ ghi chú riêng — không giẫm chân nhau. Nhu cầu này đẻ ra KernelSession, StateStore, SessionFactory.

§Câu đố

đoán trước khi lật
Kernel thì shared + frozen (dùng chung, đông cứng). Vậy chỗ nào giữ bộ nhớ riêng của một task đang chạy — và vì sao KHÔNG để chung trong kernel?
KernelSession giữ per-run state. Tách khỏi kernel vì kernel là shared: nếu nhét message history / task state vào kernel, run này ghi đè state run kia → rò rỉ giữa các run (docs/system-architecture.md:155-163, core/session.py:49-51).

Chia đôi rạch ròi: cái gì dùng chung + bất biến ở kernel; cái gì riêng + thay đổi ở session. Đây là insight cốt lõi để hết "rối".

▦"Tôi là ai" — SessionIdentity

Mỗi field là một correlation ID để trace/log nối được các sự kiện về đúng một run/agent.

FieldLà ID gì
session_idđịnh danh phiên này (một task = một session).
run_idđịnh danh cả lần chạy (gốc + các con cùng run_id).
task_idđịnh danh task cụ thể.
agent_idagent nào đang chạy (mặc định agent:root).
parent_session_idsession cha (None nếu là gốc).
delegation_idID của lần giao việc sinh ra session con (None nếu gốc).
depthđộ sâu đệ quy (gốc = 0, con = cha+1).

⌥Slice — substrate (kernel) vs per-run (session)

Cái gì dùng chung & bất biến · cái gì riêng & thay đổi

Hết "rối" khi bạn phân được hai nhóm này. Một bên là nền móng đông cứng; bên kia là bộ nhớ sống của từng task.

Kernel — shared, frozen

  • registry (danh mục tool)
  • events (EventBus dùng chung)
  • config (đông cứng khi freeze)
  • middleware pipeline

Session — riêng, thay đổi

  • state (current_task, last_result)
  • identity (các correlation ID)
  • allowed_capabilities (scope)
  • _closed (vòng đời)
Ghi chú phạm vi: create_child (giao việc cho agent con — scope hẹp hơn cha) có tồn tại nhưng Chương 9 mới đào sâu. Ở đây chỉ cần biết: con luôn là tập con của cha.
